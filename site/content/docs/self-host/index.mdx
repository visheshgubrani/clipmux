title: Self-host ClipMux
icon: Compass
nav: Overview
description: Install ClipMux on your own server, then connect storage, encoding and delivery.
---

ClipMux runs as three containers on one Linux server: the app (one Go
binary with its built-in encoder), Postgres, and Caddy for TLS. Out of the
box it stores videos on the server's disk, encodes them on the server's GPU
or CPU, and serves playback itself. Each of those can move later, to a
bucket, a rented GPU or Cloudflare's edge, without changing the API your
apps call.

You need a Linux server (amd64 or arm64) with Docker and Compose v2. Point
two DNS names at it for production TLS (one for the dashboard and API, one
for media), or run it on alternate ports or locally first. Install with the
one-line installer or directly with
[Docker Compose](/docs/self-host/install-options/docker-compose):

```bash
curl -fsSL https://clipmux.com/install.sh | sudo sh
```

The installer puts ClipMux, Postgres and Caddy in `/opt/clipmux`, generates
the database password and the secrets key, auto-detects a GPU, picks free
fallback ports if 80, 443 or 8080 are busy, starts the stack, and prints the
address and a setup token. Run the same command again to upgrade in place;
the data, keys and sessions are kept.

ClipMux runs as one server process. It doesn't run as several replicas
behind a load balancer.
