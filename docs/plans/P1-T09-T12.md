# Phase 1 — T09 to T12 slices

The detailed slice list behind the T09–T12 rows of [P1-core-product.md](P1-core-product.md),
agreed 2026-11-05. Decisions land in [../decisions.md](../decisions.md) as each task finishes.

## Context

M1 (T01–T08) is done: an API upload is encoded, encrypted, committed and played
through signed built-in delivery. Phase 1 can't exit until the rest of
docs/plans/P1-core-product.md lands. Exploring the code turned up work that no
row owns but the exit criteria or the LMS gate need; the user placed it:

- `DELETE /v1/assets/{id}` and `GET /v1/assets?updated_since=` go in **T09**
  (the only producer of `video.asset.deleted`; the webhook catch-up path).
- Reencode and playback-ID add/revoke become a new **T09b**, done before T12.
- Full worker-sandbox hardening (no network, rlimits, CPU cap) goes **inside T10
  packaging**, proven in the Docker image.
- Dashboard: Vite + React + TS, React Router, Tailwind 4, a few shadcn/ui components.
- Exit test automates **Safari (macOS runner) and ExoPlayer (Android emulator) in CI**.

Video.js check (2026-11-05): 10.0.0 stable 1 Oct 2026 (10.1.0 12 Oct; CDN 10.3.0).
`<hlsjs-video>` (`@videojs/hlsjs-video`, pins hls.js 1.7.3) takes a raw hls.js
config via `source.engine.hlsJs` and exposes the `Hls` instance as `engine`. hls.js
loads playlists, segments **and AES-128 keys** through `config.loader`, and never
retries a 4xx — so a loader wrapper is the one place to refresh tokens. → **Video.js
10**, gated by a spike; fallback Video.js 8 + VHS `xhr.onRequest`.

Facts the design rests on: `outbox.AssetEvent` (internal/outbox/outbox.go:29)
writes events from the asset row read *before* the change and without the full
asset; `webhook_endpoints.secret_encrypted` exists but no encryption helper does;
`serve` registers `defer stop()` before `defer wg.Wait()` (server.go:163-166), so a
failing listener hangs it; delivery serves only the current content-key version
(delivery.go:249); nothing creates the internal signing key; URLs are captured at
boot (server.go:117,148,156,193); no TS exists in the repo.

**Order:** T09 → T09b → T10.1–T10.7 → T11 → T10.8 (dashboard, consumes T11) → T12.
T10.6 (sandbox) and T11 touch disjoint files and can run in parallel sessions.
One commit per slice group (`P1-T09 …` style). Before each commit: `make lint`,
`make test-db`, `make sqlc-check`, `gofmt -l .` empty; TS: `pnpm -r typecheck test`.
Each task ends by updating docs/decisions.md, docs/known-gaps.md and the P1 table.

## T09 — Webhooks, delete, catch-up

**Migration 00005:** `webhook_deliveries` (id `whd_`, project_id, event_id→outbox,
endpoint_id, status pending|delivered|failed, attempts, next_attempt_at, give_up_at,
last_status, last_error ≤200, created_at, finished_at; UNIQUE(event_id, endpoint_id);
CHECKs tying status to next_attempt_at/finished_at; due index), index
`webhook_endpoints(app_id) WHERE disabled_at IS NULL`, `assets(app_id, updated_at, id)`,
`jobs_control_due` for move/delete jobs, `projects.secrets_check bytea`. Working Down.

**Packages:** new `internal/secrets`, `internal/webhooks` (sign, endpoints,
publisher), `internal/lifecycle` (delete now; reencode/playback IDs in T09b — kept out
of `assets` to avoid an assets→outbox→assets cycle). Queries: `queries/webhooks.sql`,
`queries/lifecycle.sql`.

Slices (each red → green):
1. **serve hang fix** — `TestServeReturnsWhenTheListenerFails`: reorder defers, shut
   down on the error path too.
2. **Signature** — `TestSignatureMatchesTheLMSVector`: secret `test-secret`, ts
   `1700000000`, body `{"job_id":"abc","stage":"video"}` →
   `sha256=fac6876fcc981593ebc1248ba3ce771b001862c52f3863ff0a728f73c6a44e2f`.
   HMAC over `${ts}.${body}`, secret = raw UTF-8 of `whsec_…`, hex.
3. **Secrets at rest** — AES-256-GCM, layout `0x01|key_version u32|nonce12|sealed`,
   AAD `"clipmux-secret-v1\n{table}\n{row_id}"`; key from `CLIPMUX_SECRETS_KEY`, else
   `{data_dir}/secrets.key` (0600, created by serve only; admin only loads). Literal
   vector computed separately (Python AESGCM). `projects.secrets_check` sealed on first
   boot and verified every boot → `TestServeRefusesAKeyThatCannotOpenStoredSecrets`.
4. **Endpoints** — `webhooks.CreateEndpoint` (reused by the T10 dashboard), `clipmux
   admin create-webhook --app NAME --url URL` prints `whsec_…` once; http/https only,
   no userinfo; owner-only, so no SSRF filter (recorded).
5. **Full-asset events** — `AssetEvent(ctx, q, assetID, type, baseURL, job *Job)`
   re-reads the asset in-tx and embeds `assets.Load`; `queue.Queue` gains `BaseURL`;
   `View` gains `updated_at` and per-ID `status`. Payload:
   `{"id","type","created_at","data":<GET view>,"job":{"id","kind","error_code"}?}`.
   Update callers at outputs.go:352/354, queue.go:476, uploads.go:436.
6. **Fan-out** — lock pending `kind='webhook'` outbox rows SKIP LOCKED, one delivery per
   enabled endpoint of the row's app (`ON CONFLICT DO NOTHING`), `MarkOutboxDone`.
7. **Send** — claim with one `UPDATE … attempts+1, next_attempt_at=now()+60s … SKIP
   LOCKED RETURNING`; send outside the tx, 8 in flight, 32 per pass; record fenced on
   `attempts`. Headers: Content-Type, X-Webhook-Event, X-Webhook-Id,
   X-Webhook-Timestamp (fresh per attempt), X-Webhook-Signature,
   `User-Agent: ClipMux-Webhooks/1.0`. Sign the exact stored bytes.
8. **Retry** — any 2xx succeeds; no redirects (3xx fails); 10 s timeout; body read ≤4 KiB;
   errors stored as codes only. Offsets 30s, 2m30, 12m30, 42m30, 1h42m30, 3h42m30,
   7h42m30, 15h42m30, 23h42m30, last clamped to 24h, then `failed`. Disabled
   endpoint/app → `endpoint_disabled`/`app_disabled`, nothing sent. Lease expiry resends.
9. **Loop** — `sweeper.Every(ctx, 5*time.Second, "webhooks", pub.Run)` in serve.
10. **Unpublish** — route payload gains `"op":"unpublish"`; `SyncRoutes`
    (outputs.go:287) moves revoking → revoked; export `outputs.QueueRoute`/`QueueUnpublish`.
11. **DELETE /v1/assets/{id}** (`assets:write`) — one tx via `queue.LockForChange`
    (upload → job → asset, re-check active job): cancel upload and jobs, mark asset
    deleted (error_code NULL, version+1), playback IDs revoking + unpublish rows, enqueue a
    control-plane `delete` job. Runner (server loop, never claimable by workers): wait for
    routes, `AbortMultipart` + `DeletePrefix` on `uploads/{id}/` and `media/{id}/`, write
    `video.asset.deleted` once, then a second storage pass at job end + 16 min (outlives
    15-min PUT URLs). Request runs it inline up to 10 s → 200, else 202; GET keeps
    returning `status:"deleted"`. Tests: ready asset stops playing at once and files
    vanish; running job's worker is told to stop and a late file is swept; waiting upload
    is aborted; idempotent, app-scoped, scope-checked, resumes after a crash.
12. **Catch-up** — `GET /v1/assets?updated_since=RFC3339&cursor=`: inclusive, ordered
    `(updated_at, id)`, ≤100 per page, opaque cursor, deleted included; docs tell clients
    to overlap 5 min and dedupe on version.

Decisions: D017 secrets at rest, D018 webhooks, D019 delete, D020 catch-up.
Known gaps: add no endpoint disable/rotate before T10, no circuit breaker, outbox and
delivery rows never pruned, no SSRF filter on owner URLs, no secrets-key rotation,
`reencode_failed` invisible to catch-up; remove the "not delivered / provisional
payload / encryption columns unused / list only by passthrough" lines.

## T10 — First boot, management API, sandbox, packaging, dashboard

**T10.1 Server keys in Postgres.** Migration: `content_key_secrets(project_id,
version, secret_encrypted, PK(project_id, version))`; partial unique index for one
active internal key per project. `contentkey.Ring` (`Current()`, `Get(v)`), imported
once from an existing `content.key` (removed only after the DB copy decrypts to the
same bytes); delivery uses `ring.Get(out.KeyVersion)`; boot refuses if any output's
version is missing. New `internal/signingkeys` (`Create` moved from admin.go,
`EnsureInternal`, `Internal()`). Storage URL-signing key moves into
`storage_configs.secrets_encrypted` (second import-once case → extract the helper).
Tests: ciphertext only + same key after reload; file imported once; every used version
served (key/3 → 404); internal key created once and accepted for any app.

**T10.2 URL settings.** Migration: rename `projects.media_hostname` → `media_url`
(origin), add `urls_confirmed_at`. New `internal/settings` (atomic snapshot,
`PublicURL()`, `MediaURL()`, `Pinned()`, `KeysAllowed()`, `Set()`). Env
`CLIPMUX_PUBLIC_URL`/`MEDIA_URL` **pin** (step read-only, 409 `pinned`). Every boot-time
URL consumer takes `func() string`. `GET /_tls/ask?domain=` for Caddy on-demand TLS.
Key gate: 409 `public_url_required` while loopback; `admin create-key
--allow-loopback` for dev/e2e. Built-in worker gets `--storage-via-server` so signed
`/_storage/` URLs go over loopback, not the public hairpin. Tests: saved URLs apply
without restart; ask allows only configured hosts; localhost/127.0.0.1/`*.localhost`
→ 409, `192.168.1.10` → 201.

**T10.3 Owner and sessions.** Migration: `owners` (UNIQUE project_id → registration
closes atomically), `owner_sessions` (token_hash PK, expires). `internal/accounts`:
PBKDF2-SHA256 (stdlib `crypto/pbkdf2`, 600k, 16-byte salt, rehash on login), min 12
chars; setup token in memory, printed only while no owner exists, constant-time
compare; cookie `__Host-clipmux_session` (https) / `clipmux_session`, HttpOnly,
SameSite=Strict, 30 d / 7 d idle, stored hashed; `http.CrossOriginProtection` + JSON
bodies; login throttle 5/15 min/IP, 20 global, `CLIPMUX_TRUSTED_PROXIES`; routes
`/v1/setup`, `/v1/setup/owner`, `/v1/session`; `clipmux admin reset-password` (stdin,
ends sessions). TOTP → known gap. Tests incl. concurrent registration creates exactly
one owner, password hash matches a Python worked example.

**T10.4 Management API** (public, documented in `docs/api.md`). Uploads/assets take an
`Authenticate func(*http.Request) (apikeys.Key, error)`: bearer first, then session; the
owner acts as one app (`ClipMux-App` header, default `app_dashboard`). Owner-only:
`/v1/apps`, `…/api-keys` (shown once, revoke), `…/signing-keys`, `…/webhook-endpoints`
(T09 tables), `GET /v1/library` (all apps, keyset), `POST
/v1/assets/{id}/preview-token` (internal key, 1 h). Tests: integration key can't manage
apps; owner upload lands in the Dashboard app; disabling an app stops keys and playback.

**T10.5 Sample clip + setup test.** Migration `setup_tests` (status, trigger, checks
jsonb, one active per project). Embedded `internal/setuptest/sample.mp4` (8 s, 640×360,
~250 KB) from a committed `toolchain/make_sample.sh` with sha256 — no ffmpeg in the
control plane. The runner (sweeper loop) creates the upload in-process, then does
everything a browser does over HTTP through the real public/media URL
(`CLIPMUX_SELF_DIAL` lets compose dial Caddy with the public SNI/Host). Checks: v plays,
16-byte key, decrypted segment has `moof`; t → 403 on segment and key, 200 on poster; no
token → 403; stored segment has no `moof` in its first 64 bytes. Triggers: URL save, `POST
/v1/setup-test`, `clipmux admin setup-test --wait`. Details never carry URLs or tokens.

**T10.6 Tool sandbox** (parallel-safe). New `internal/sandbox` (Linux + stub), hidden
`clipmux sandbox-exec [--read P] [--write D] -- tool args`; `media.Tools` routes `run`
(run.go:158) through it. Before `syscall.Exec`: rlimits (AS 8 GiB configurable, FSIZE,
NOFILE, CORE 0, CPU from job budget), nice 19 + SCHED_IDLE, `no_new_privs`, seccomp
(`socket()` → EACCES; io_uring/ptrace/bpf/userfaultfd → EPERM), Landlock best effort.
Network namespaces and cgroups don't work in default Docker, hence this design; compose
`cpus:` is the hard cap. Rlimits, no_new_privs and seccomp are required, else the
built-in worker stays off (override `CLIPMUX_UNSANDBOXED_WORKER=true`); `--probe` reports.
Tests: ffmpeg can't open a socket; can't read `secrets.key`; memory limit stops a
runaway decode; idle priority; golden transcode passes sandboxed.

**T10.7 Packaging.** `Dockerfile` (toolchain stage: `build_ffmpeg.sh` with a BuildKit
cache + `install_packager.sh`; Go `CGO_ENABLED=0 -trimpath`; runtime ubuntu:24.04 +
`CLIPMUX_RUNTIME_PACKAGES` + tini, `verify_toolchain.sh`, uid 10001, `clipmux
healthcheck`), `.dockerignore`, `deploy/compose.yml` (app read_only, cap_drop ALL,
no-new-privileges; postgres:18-alpine; caddy:2 with a static on-demand-TLS
`deploy/Caddyfile`, `/_tls/*` blocked outside). CI image job, never pushed (D005/D006):
compose up → sandbox probe → socket negative check → `admin setup-test --wait` →
`/healthz` through Caddy. Cache keyed on versions.env + build_ffmpeg.sh.

**T10.8 Dashboard** (after T11). `dashboard/` workspace member (Vite, React, React
Router, Tailwind 4, shadcn Button/Input/Dialog/Table/Card/Sonner) using
`@clipmux/uploader` and `@clipmux/player` via `workspace:*`. Build into
`internal/web/dist` (gitignored except `.gitkeep`), embed `all:dist placeholder.html` so
`go build` works without Node. SPA handler: real files (`assets/*` immutable); reserved
prefixes (`/v1/ /v/ /p/ /_storage/ /worker/ /_tls/ /healthz /readyz`) → JSON 404; else
`index.html` no-store. Pages: setup wizard (token → owner → URLs → setup test → sample
plays), login, library, upload, asset detail with player, apps (keys, signing keys,
webhooks; secrets shown once). Dockerfile gains a web stage.

Decisions D022–D028 (keys in Postgres, URL settings, owner auth, management API, setup
test, sandbox, packaging/dashboard build). Known gaps: close M1 sandbox subset,
`content.key` file, no Dockerfile, setup token every boot, internal key, unused
encryption columns, stale "not implemented" lines; add TOTP, share links, Landlock on
old kernels, CPU priority not quota, key rotation at next boot, one-replica
limiter/setup token, secrets key in the data volume when env unset.

## T11 — `@clipmux/uploader` and `@clipmux/player`

**Workspace:** root private `package.json` (`packageManager: pnpm@12.11.2`, node ≥24),
`.node-version`, `pnpm-workspace.yaml` (`packages/*`, `dashboard`, `e2e/web`). Build with
plain `tsc` (ESM + d.ts), tests with `node --test` (type stripping, `mock.timers`), lint
with Biome. Versions `0.3.0`, `"private": true` until launch. New `ts` CI job.

**Uploader** (zero deps): `new ClipMuxUpload(file, {endpoint, upload /* create body
from the app's backend */, concurrency: 4, onProgress, signal, fetch, put, delay,
random})` with `start/pause/resume/cancel`, plus `rememberUpload(storage)` that saves only
`upload_id, upload_token, part_size, part_count`. List-parts is the source of truth: check
part_count, `GET /parts`, upload only missing parts, complete with ETags as received.
`upload_not_active` → probe complete once (sweeper may have finished it). Sign ≤100
missing parts, re-sign within 5 min of `expires_at`, storage 403 → re-sign once. Backoff
`min(30 s, 1 s·2^n)` + jitter, 6 tries, waits for `online`; fatal errors reject with
`ClipMuxUploadError {code, status, retryable}` and never cancel the server upload. XHR
for byte progress. Tests (ported + new): literal part plan for 73400320 bytes; resume
with parts 1–2 listed PUTs only 3; 250 parts sign as 1–100/101–200/201–250; 503,503,200
waits `[1000,2000]`; Retry-After 7 → 7000; ≤4 PUTs at once; progress `[0,4,8,10]`.

**Player:** slice 1 is the **spike** — `<hlsjs-video>` with a logging
`source.engine.hlsJs.loader` against the T12 fixture must see master, both playlists,
`key/1` and segments, decode audio, and pass in Chromium and once in macOS Safari; else
switch to the v8 fallback (recorded). Then `<clipmux-player base-url playback-id>` with
`token`, `getToken: () => Promise<string|null>`, `hls` properties and
`clipmux-token/denied/error` events; exports `clipmuxSource()`, `rewriteTokenUrl()`,
`createRefreshLoader()`; JSX types for React 19, no React dependency. Rewrite only for
the media origin: `^/v/[^/]+/(?=${pid}/)` → `/v/${current}/`. Loader wrapper: rewrite
every request; 401 → retry at once if a newer token exists, else one coalesced
`getToken()` and reload through a fresh inner loader (hls.js never sees the error, so
position is untouched); second 401 passes through; 403 → denied, stop; 404 passes
through; `null` → denied; throw → retry 1/2/4 s. Reactive only, no timers. Native HLS (iOS
< 17.1, AirPlay, Chromecast) can't refresh — README documents the lifetime rule; iOS
17.1+ plays via ManagedMediaSource and does refresh (amends D014).

Decisions D029 (Video.js 10 + refresh loader, D014 amendment), D030 (TS workspace),
D031 (uploader resume and retry table).

## T12 — Exit test

**Rig:** test-only `internal/e2e` (`*_db_test.go`, skipped unless `CLIPMUX_E2E=1`).
`TestMain` builds `cmd/clipmux` (or `CLIPMUX_E2E_BIN`); each test boots the real `serve`
on a `dbtest` schema (`search_path` in `DATABASE_URL`), free port, temp data dir, tools on
PATH, waits on `/readyz`; keys through `admin create-key --allow-loopback` /
`create-signing-key`; fixture = lavfi 1280×720 25 fps + 440 Hz, 30 s, uploaded through
the real API.

Go suites: real binary plays (ffmpeg as HLS client); **kill-a-worker** — find serve's
worker child via `/proc`, SIGKILL once ffmpeg runs, assert attempts `[lost, committed]`,
`lost_count=1`, current output is attempt 2's, plays (real 90 s lease, ~2.5 min) — plus the
fix that the supervisor clears `{data}/worker` before each child start
(builtin_worker.go:73); **setup test** — fresh install, first boot via the logged token,
`admin setup-test --wait` passes every check.

Browser suites (`TestPlayerFixture` serves `e2e/web` pages, `/token?aud=&ttl=`,
`/uploads`, and a logging proxy recording token hashes only):
- Chromium/hls.js: past 8 s, 3 levels + 1 audio track, audio decoded, 16-byte key,
  wire segments not MP4, `t`/no token 403.
- Chromium/`<clipmux-player>`: 8 s token, `maxBufferLength: 4`: ≥1 401, `getToken` ≥2,
  continuous `played` 0→20 s, no error; `null` → denied.
- Chromium/uploader: 70 MiB Blob, reload after part 1 → only 2 more PUTs → processing.
- Safari (`macos-15`, safaridriver, tiny fetch WebDriver client; brew ffmpeg + Postgres,
  pinned Darwin packager): native `<video>` past 8 s with 1 audio track; proxy shows key
  and audio 200; `<clipmux-player>` refresh.
- ExoPlayer (`e2e/android`, Media3 instrumented test, android-emulator-runner API 35,
  host via 10.0.2.2, cleartext only for it): video + audio groups selected, past 8 s, no
  error, `t` token 403. Plus a Robolectric `CapturingRenderersFactory` JVM test (750 video
  samples, audio > 0).
- WebKit on Linux is not run (not Safari).

**CI:** `exit.yml` (Linux + Android; main, dispatch, weekly, PRs touching
delivery/media/worker/queue/outputs/uploads/server/e2e/packages/toolchain) and
`exit-safari.yml` (narrower paths, 20 min). Cancel superseded runs; upload logs on
failure.

Decision D032 (harness, cadence, real lease defaults, no Linux WebKit). Known gaps:
iPhone checked manually, no Firefox in CI, fetch progress per part, runner image drift
caught weekly. Then mark Phase 1 exit in the P1 plan and run docs/plans/launch.md.
